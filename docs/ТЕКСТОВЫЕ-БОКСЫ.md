# Текстовые боксы — руководство для интерфейса

Документ для того, кто выводит в игре любой текст: реплику звонка, статью
энциклопедии, отчёт на компьютере, титры катсцены, вводную на выезде.

Правило одно: **текст не пишется в сцене и не приходит в событии — он берётся по id.**
Всё остальное здесь — про то, как это делается с минимумом кода.

Исходники: `scripts/ui/ContentTextBox.cs`, пример наследника —
`scripts/ui/EncyclopediaTextBox.cs`. Схема самих текстов —
`content/raw/_system/Syntax/README.md`.

---

## 1. Как это устроено

```
   content/raw/**/*.md
        │  python content/engine/converter/build.py
        ▼
   content/localisation/<локаль>/**/<тип>.json
        │  автозагрузка Content
        ▼
   ContentEntry { Chunks[], Properties[], ... }
        │  ContentTextBox: фильтр по флагам GameState
        ▼
   Render() у наследника
```

Автор правит `.md` в Обсидиане, конвертер собирает JSON и падает на битом контенте,
`Content` держит всё в памяти, `ContentTextBox` отдаёт наследнику готовый список кусков.

**Кусок (chunk) — единица текста.** В исходнике это абзац, разделённый пустой строкой.
Для нижнего текста один кусок = один клик; для энциклопедии — один абзац статьи. Как их
показывать, решает наследник, базовый класс только говорит, какие куски видны сейчас.

**Базовый класс ничего не рисует.** Он отвечает ровно за две вещи: достать запись по id
и выбросить условные абзацы, которые игра ещё не открыла. Ни вёрстки, ни пагинации, ни
эффекта печатной машинки в нём нет и не должно быть — это разное у каждого экрана.

## 2. Быстрый старт

Минимальный бокс — четыре строки содержательного кода:

```csharp
using System.Text;
using Godot;

public partial class ReportBox : ContentTextBox
{
    [Export] public NodePath LabelPath { get; set; } = new("Label");

    private RichTextLabel _label;

    public override void _Ready()
    {
        // Ярлык нужен до base._Ready(): тот сразу вызовет Render().
        _label = GetNode<RichTextLabel>(LabelPath);
        base._Ready();
    }

    protected override void Render()
    {
        var text = new StringBuilder();
        foreach (ContentChunk chunk in Chunks)
        {
            text.Append(chunk.Text).Append("\n\n");
        }

        _label.Text = text.ToString().TrimEnd('\n');
    }
}
```

В сцене выставить `ContentId` в инспекторе — и бокс наполнится сам. Либо оставить пустым
и позвать `Open("report_black_mold_carpets_success")`, когда придёт событие.

**Порядок в `_Ready` важен.** Сначала получить свои узлы, потом `base._Ready()`.
Базовый класс в конце своего `_Ready` грузит `ContentId` и вызывает `Render()`; если
ярлык ещё не найден, первый кадр отрисуется в пустоту.

## 3. Что даёт базовый класс

### Свойства в инспекторе

| Поле | Смысл |
|---|---|
| `ContentId` | Какую запись показывать. Меняется и в рантайме — через `Open()`. |
| `OpenOnReady` | Грузить `ContentId` сразу. Снять, если бокс наполняется по событию. |
| `RevealEverything` | Показать все условные абзацы, не спрашивая игру. Только для превью вёрстки. |
| `RefreshOnReveal` | Перечитывать себя, когда меняется флаг или открывается абзац энциклопедии. |

### Доступно наследнику

| Член | Смысл |
|---|---|
| `Chunks` | Видимые куски в порядке файла. Пустой список, если записи нет. |
| `Entry` | Вся запись целиком: `Properties`, `Requirements`, `Name`, `Outcome`, `Day`, `Options`. |
| `CallMeta` | Шапка звонка («ЗВОНОК ПЕРЕНАПРАВЛЕН ИЗ ЖЭК»), пустая строка, если её нет. |
| `IsLoaded` | Запись нашлась. |
| `Open(id)` | Показать другую запись. Пустой id очищает бокс. |
| `Refresh()` | Перечитать флаги и перерисовать, ничего не перезагружая. |
| `IsChunkVisible(chunk)` | Тот же вопрос, по которому собран `Chunks` — если идёшь по `Entry.Chunks` сам. |

### Что можно переопределить

| Метод | Зачем |
|---|---|
| `Render()` | Обязательный. Нарисовать `Chunks`. |
| `IsRevealed(propertyId)` | Если флаги живут не в `GameState`. Единственная точка про условность. |
| `OnMissingContent(id)` | Если ненайденный id — не ошибка, а штатная ситуация. |

`Render()` зовётся при каждом `Open()` и `Refresh()`, **в том числе с пустым списком** —
наследник обязан уметь чистить себя, а не только наполнять.

## 4. Условные абзацы

В тексте условный абзац помечен id свойства:

```markdown
%% reveal: property_mimic_routine %%
Мимик крайне чувствителен к нарушению рутины.
%% /reveal %%
```

Базовый класс сам решает, показывать его или нет, и в `Chunks` скрытые куски просто
не попадают. По умолчанию вопрос задаётся ядру в два шага:

1. **Сюжетный флаг** с именем, равным id свойства — `Session.IsFlagSet("property_mimic_routine")`.
2. **Раскрытия энциклопедии** — свойство могло открыться отчётом с выезда.

Поставить флаг из игрового кода:

```csharp
GameRuntime.Get(this).Session.SetFlag("property_mimic_routine");
```

Дальше ничего делать не нужно: ядро публикует `FlagChanged`, и все боксы с
`RefreshOnReveal` перечитывают себя сами. Вручную `Refresh()` звать не надо.

Флаги живут в `GameState.Flags` (`kontur-core/src/Kontur.Core/Systems/FlagSet.cs`),
обнуляются при новой партии, регистр имени не важен.

**Заглушки вместо скрытого текста.** Если нужно показать, что абзац есть, но закрыт,
иди по `Entry.Chunks` и спрашивай `IsChunkVisible` — так сделано в `EncyclopediaTextBox`:

```csharp
foreach (ContentChunk chunk in Entry.Chunks)
{
    if (IsChunkVisible(chunk)) { builder.Append(chunk.Text); }
    else { builder.Append("[ДАННЫЕ НЕ ПОДТВЕРЖДЕНЫ]"); }
}
```

## 4a. Подсветка ключевых слов

В тексте вызова автор помечает зацепки — `У меня ==дочка маленькая==`. Виджет красит их,
чтобы игрок понял, кого отправлять. Какую характеристику слово подсказывает, в контенте
не хранится и игроку не показывается: сопоставление — его работа.

Кусок с разметкой несёт `Spans` — текст, разбитый по порядку на отрезки, где у ключевых
слов взведён `Highlight`, а у подписей и ярлыков (`**Расходник.**` в описании снаряжения)
— `Bold`. Пустой `Spans` значит «размечать нечего». Собирать разметку руками не надо:

```csharp
_label.Text = chunk.ToBbcode();   // [color=#d27253]дочка маленькая[/color], [b]Расходник.[/b]
```

`ToBbcode()` экранирует квадратные скобки самого текста, так что `[1985]` в реплике не
разберётся как разметка. Цвет по умолчанию — `ContentChunk.HighlightColor` (`#d27253`),
один на все характеристики; хочешь другой — передай параметром.

Отрезки, а не позиции в тексте, — потому что подстановка `{{имя}}` меняет длину и любые
смещения после неё уехали бы.

## 5. Типы записей и что от них ждать

| Тип | Папка | Особенности |
|---|---|---|
| `call` | `calls/` | Кусок ≤150 символов (две строки), бывает `CallMeta`. `MissionType` — `radio` или `filler`. Куски бывают с подсветкой ключевых слов. |
| `cutscene` | `cutscenes/` | То же ограничение, тот же виджет нижнего текста. |
| `radio` | `radio/` | Кроме `Chunks` есть `Options` — блоки решений. |
| `creature` | `creatures/` | `Name`, условные абзацы, `Properties` со списком свойств. |
| `report` | `reports/` | `Outcome` — исход миссии. |
| `shift_note` | `shift_notes/` | `Day`. |
| `perk` | `UI/hover_footnote/perks/` | `Name`. `id` совпадает с id способности в `data/abilities.json`. |
| `characteristic` | `UI/hover_footnote/characteristics/` | `Name` — подпись в досье, `Chunks` — описание. `id` совпадает с `StatKinds.GetId(kind)`. |
| `equipment` | `equipment/` | `Name` — название, `Chunks` — описание, эффект и подпись вида. `id` совпадает с id в `data/equipment.json`; `EquipmentSlotView` отдаёт только его. |
| `equipment_kind` | `UI/hover_footnote/equipment_kinds/` | Сноска по наведению на подпись вида. `id` — `EquipmentKind` в нижнем регистре. |
| `scale` | `UI/hover_footnote/scales/` | Название шкалы для блокнота и сноска, что она значит. `id` совпадает с `ScaleKinds.GetId(kind)`. |

У `radio` варианты лежат в `Entry.Options`, каждый со своим `Name`,
`RequirementModifier` и собственными `Chunks`. Базовый класс их не фильтрует —
бокс с решениями пока никто не написал, это следующий кандидат на наследника.

Названия характеристик берутся отсюда же. Ядро их не знает — `StatKinds.GetId(kind)`
отдаёт id, он же id записи:

```csharp
ContentEntry stat = Content.Instance.GetEntry(StatKinds.GetId(StatKind.Composure));
nameLabel.Text = stat.Name;                  // «Хладнокровие»
descriptionBox.Open(stat.Id);                // описание — обычные Chunks
```

## 6. Как переписывать существующий вывод текста

Порядок для любого места, где сейчас текст приходит строкой:

1. **Найти текст в `content/raw/`** или завести там запись, если её нет. Реестр id —
   `content/raw/_system/ids_registry.md`, генерируется конвертером.
2. **Сделать наследника** `ContentTextBox` под конкретный экран. Одна вёрстка = один класс.
3. **Заменить строку на id.** Вместо `label.Text = e.BriefingText` — `box.Open(e.MissionId)`.
4. **Пересобрать контент**: `python content/engine/converter/build.py`. Черновики
   (`status: draft`) в обычную сборку не попадают — для проверки `--include-drafts`.

Что при этом *не* надо делать: держать текст в `.tscn`, склеивать строки в C#,
передавать прозу в событиях, проверять флаги в самом виджете.

### Что уже переведено на id, а что ещё нет

**Переведены:** энциклопедия, снаряжение, перки, характеристики, шкалы. В геймплейных
данных от них остались только id и числа — ни имени, ни описания. `EquipmentSlotView`
отдаёт `Id` и `Kind`, `StatKinds.GetId` и `ScaleKinds.GetId` — один id, события существ
несут `CreatureId` и `PropertyId`.

Ядро при загрузке сверяет свои id с текстами через порт `ITextCatalog`
(реализация — `scripts/kontur/GodotTextCatalog.cs`), поэтому опечатка в id падает на
старте с внятным сообщением:

```
Существо 'creature_mimic': в статье нет блока %% reveal: property_mimic_TYPO %%
```

**Ещё нет.** Проза по-прежнему приходит из `data/*.json` в событиях:
`ShiftStarted(ShiftNoteTitle, ShiftNoteText)`, `CallAnswered(Title, BriefingText)`,
`RadioTriggered(SituationText)`, `RadioOptionChosen(OptionText)`, плюс имена сотрудников
в `EmployeeView` и в четырёх событиях. Для этих строк пока два источника правды.
Переводятся тем же приёмом, что и существа, — по одному типу за раз.

У миссий, написанных после этого перехода, поля `briefingText`, `reportSuccessText`,
`reportFailureText` и `situationText` уже пустые: текст лежит в `calls/`, `radio/` и
`reports/` под тем же слагом, что и id миссии.

Если пишешь новый бокс — бери текст из `Content` по id, даже если рядом лежит готовая
строка из события.

## 7. Грабли

**BBCode.** `RichTextLabel` с `BbcodeEnabled = true` разберёт любую квадратную скобку в
тексте как разметку: `[1985]` или `[i]` испортят абзац. Либо выключай bbcode, либо
экранируй `[` в `[lb]`.

**`[[type:id]]` в тексте не разворачивается.** Конвертер проверяет, что цель ссылки
существует, но в JSON она лежит как есть, и рантайм её не обрабатывает — игрок увидит
`[[creature:creature_mimic]]` буквально. Пока просто не ставь такие ссылки в текст,
который уже показывается.

**Пустой `Chunks` — нормальная ситуация.** Запись не нашлась, все абзацы условные и
закрыты, `Open("")`. `Render()` должен это переживать.

**Подписки.** Базовый класс сам снимает свои подписки в `_ExitTree()`. Если наследник
подписался на что-то своё — снимай сам, и не забудь позвать `base._ExitTree()`.

**Автозагрузки.** Нужны `Content` (тексты) и `GameRuntime` (флаги). Если их нет, бокс не
падает: пишет предупреждение в Output и остаётся пустым.
