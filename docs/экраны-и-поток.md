# Экраны и поток игры

Документ для того, кто добавляет новый экран или меняет порядок существующих:
меню, стартовый выбор, ролик, смена, найм.

Про то, как разговаривать с симуляцией, — `docs/ядро-api.md`.
Про то, как выводить текст, — `content/raw/_system/текстовый-движок.md`.

---

## 1. Кто чем занят

```
   MainMenu ──► HiringScreen (стартовый выбор) ──► main.tscn (кабинет)
       ▲                                                  │
       │                                                  ▼ ShiftEnded
       └───────── CutscenePlayer ◄── HiringScreen ◄── CutscenePlayer
```

Порядок держит **`GameFlow`** — автозагрузка, один узел на всю игру
(`scripts/flow/GameFlow.cs`).

Это сделано намеренно. Как только каждая сцена начинает знать про следующую,
правило «после смены сначала ролик, потом найм» расползается по трём файлам,
и поменять его становится страшно. Здесь оно в одном месте — в `OnShiftEnded`.

| Экран | Сцена | Скрипт |
|---|---|---|
| Главное меню | `scenes/ui/menu/MainMenu.tscn` | `scripts/ui/MainMenu.cs` |
| Ролик | `scenes/ui/cutscene/CutscenePlayer.tscn` | `scripts/ui/CutscenePlayer.cs` |
| Набор людей | `scenes/ui/hiring/HiringScreen.tscn` | `scripts/ui/HiringScreen.cs` |
| Кабинет | `scenes/main.tscn` | предметы на столе |

Состояние партии живёт в ядре и **переживает смену сцен**: `Kontur` и `GameFlow` —
автозагрузки, их не выгружает `ChangeSceneToFile`. Поэтому экрану не нужно ничего
никуда передавать, он спрашивает у ядра сам.

## 2. Как переключать экраны

Из любого места:

```csharp
GameFlow.Instance.StartNewGame();          // новая партия
GameFlow.Instance.ContinueGame();          // из быстрого слота, false если нечего грузить
GameFlow.Instance.ShowMainMenu();
GameFlow.Instance.BeginShift(day);         // начать смену и уйти в кабинет
GameFlow.Instance.PlayCutscene(id, next);  // ролик, затем указанная сцена
GameFlow.Instance.ShowHiring(day, isStartingChoice: false);
```

Экран, который закончил работу, сообщает об этом обратно:

```csharp
GameFlow.Instance.OnCutsceneFinished();   // ролик доигран или пропущен
GameFlow.Instance.OnHiringFinished(day);  // набор закончен
```

**Симуляция ставится на паузу на всех экранах, кроме кабинета.** `GameFlow` дёргает
`KonturRuntime.IsPaused` сам — вручную это делать не нужно и не следует.

Пауза снимается **отложенно**, в конце кадра: сцена кабинета должна успеть
собраться, иначе первый `Tick` пройдёт по предметам, которые ещё не подписались
на события, и первый звонок никто не услышит.

## 3. Ролики между сменами

Проигрыватель ищет видеофайл, не находит — показывает текст.

```
assets/cutscenes/<id катсцены>.ogv     ← если есть, играет видео
content/raw/ru/cutscenes/*.md             ← иначе текст покусочно
```

Имя файла совпадает с **id записи**, а не с именем `.md`. Для
`cutscene_before_shift_2` нужен `assets/cutscenes/cutscene_before_shift_2.ogv`.

**Только `.ogv` (Ogg Theora).** Godot из коробки не умеет ни mp4, ни webm — кодеки
лицензируются отдельно и в сборку не входят. Конвертировать:

```
ffmpeg -i вход.mp4 -q:v 7 -q:a 5 выход.ogv
```

Текстовый режим листается пробелом, куски копятся на экране; `Esc` пропускает
целиком. Разметка ключевых слов работает та же, что в звонках, — через `ToBbcode()`.

**Отсутствие файла — не ошибка, а штатный режим.** Играть можно уже сейчас, видео
подкладывается позже без единой правки в коде.

## 4. Экран набора людей

Один экран на два случая — они отличаются только источником списка и правилом
«сколько можно взять»:

| | Стартовый выбор | Добор между сменами |
|---|---|---|
| Когда | перед первой сменой | после ролика в конце смены |
| Список | `GetStartingChoice()` | `GetHireCandidates(day)` |
| Сколько | ровно весь штат | сколько свободных мест |
| Можно пропустить | нет | да |
| Подтверждение | `ConfirmStartingRoster(ids)` | `HireEmployee(id, day)` на каждого |

Флаг режима — `GameFlow.Instance.HiringIsStartingChoice`.

При стартовом выборе кнопка «Готово» не нажимается, пока бригада не укомплектована
полностью: выйти на первую смену вдвоём вместо троих — это не решение игрока,
а недосмотр, и игра не должна его молча принимать.

**Если брать некого** — список пуст или свободных мест нет — экран закрывается сам,
не показавшись. Пустой экран найма игрок читает как поломку.

Названия перков берутся из текстового движка по id способности
(`content/raw/ru/UI/hover_footnote/perks/`), описание уходит во всплывающую подсказку.
Нет записи — показывается сам id: так пропущенный текст виден сразу.

## 5. Стартовый выбор состава

Раньше штат был жёстко прописан в `startingRoster`. Теперь фабрика готовит пул,
из которого игрок собирает первую бригаду.

Размер пула — `generator.startingChoicePoolSize` в `data/employees.json`.
Он должен быть **больше лимита штата первого дня**: смысл выбора в том, чтобы
от кого-то отказаться. Сейчас шесть кандидатов на три места.

```csharp
if (simulation.NeedsStartingChoice)
{
    IReadOnlyList<HireCandidateView> pool = simulation.GetStartingChoice();
    // ... игрок выбирает ...
    CommandResult result = simulation.ConfirmStartingRoster(chosenIds);
}
```

**`startingChoicePoolSize: 0` отключает выбор.** Тогда `NeedsStartingChoice`
возвращает ложь, штат берётся из `startingRoster` как есть, и `GameFlow` уходит
сразу в первую смену. Полезно для отладки и для сюжетных прологов, где состав задан.

Набор кандидатов фиксируется до подтверждения: список можно спрашивать хоть каждый
кадр, люди под курсором не поменяются. Подтвердить можно один раз за партию —
признак уезжает в сохранение, чтобы после загрузки выбор не предложили заново.

## 6. Как добавить свой экран

1. Сцена в `scenes/ui/<имя>/`, скрипт в `scripts/ui/`.
2. Путь к сцене — константой в `GameFlow`, рядом с остальными.
3. Метод перехода в `GameFlow` (`ShowЧтоТо`), метод возврата (`OnЧтоТоFinished`).
4. Данные экран берёт у ядра сам, через `GameFlow.Instance.Simulation`.

Чего делать не надо: передавать состояние между сценами через статические поля
и переключать сцены в обход `GameFlow`. Первое ломается на загрузке сохранения,
второе — на паузе симуляции.

## 7. Грабли

**Меню — стартовая сцена проекта.** `run/main_scene` указывает на `MainMenu.tscn`.
Отладочный оверлей никуда не делся, он в `scenes/debug/KonturDebug.tscn` — запускайте
его отдельно клавишей F6, когда нужно погонять ядро без интерфейса.

**`GameFlow` поднимается после `Kontur`.** Порядок автозагрузок в `project.godot`
значим: `GameFlow` в `_Ready` ищет ядро и подписывается на события. Поставите его
выше — получите пустую ссылку.

**Кнопка «Продолжить» гаснет, если сохранения нет.** Кнопка, которая ничего не
делает, хуже отсутствующей: игрок жмёт её и решает, что игра сломана.

**После загрузки ядро держит время остановленным** до `ResumeAfterLoad()`.
`GameFlow` вызывает его сам в конце кадра, когда кабинет собрался. Если делаете
свой путь загрузки — не забудьте отпустить время, иначе игра выглядит зависшей.

**Экран найма может закрыться мгновенно.** Это не баг: если мест нет или кандидатов
нет, он уходит дальше не показавшись. Проверять надо `HiringOpened` из ядра —
оно как раз и не приходит, когда брать некого.
