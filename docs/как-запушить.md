# Как отправить правки в репозиторий

Два способа: команды в консоли и кнопки в VS Code. Делают они одно и то же —
выбирайте, что удобнее. Есть ещё `запушить.bat` в корне проекта: тот же порядок
действий, но с проверками и без набора команд.

---

## 0. Один раз: превратить рабочую папку в клон

Пока в `C:\Users\sidef\Desktop\0-41-andy-branch` нет папки `.git`, git про эти файлы
ничего не знает. Настройка делается один раз и запоминается навсегда.

### Сначала — проверка безопасности

Откройте командную строку (`Win+R` → `cmd` → Enter) и выполните:

```cmd
cd /d "C:\Users\sidef\Desktop\0-41-andy-branch"
git rev-parse --show-toplevel
```

**Должно напечатать `fatal: not a git repository`.** Это правильный ответ:
своего репозитория ещё нет, чужого поблизости тоже.

Если вместо ошибки напечатался путь вроде `C:/Users/sidef` — остановитесь.
Это репозиторий, случайно созданный в домашней папке. Коммит при нём затянет
в историю `.ssh`, `AppData` и `.claude.json`, то есть ключи и токены. Удалите его:

```cmd
rmdir /s /q C:\Users\sidef\.git
```

и повторите проверку.

### Представиться (если git видит вас впервые)

```cmd
git config --global user.name "Ваше имя"
git config --global user.email "sideefect41@gmail.com"
```

Почта должна совпадать с той, что привязана к GitHub, иначе коммиты не свяжутся
с вашим профилем.

### Собственно настройка

Адрес репозитория берётся на его странице в GitHub: зелёная кнопка **Code** → HTTPS.

```cmd
cd /d "C:\Users\sidef\Desktop\0-41-andy-branch"
git init -b core-sim
git remote add origin https://github.com/ИМЯ/НАЗВАНИЕ.git
git fetch origin
```

Дальше зависит от того, есть ли ветка `core-sim` на сервере.

**Если есть** (а она есть — вы туда уже пушили):

```cmd
git reset --mixed origin/core-sim
git branch --set-upstream-to=origin/core-sim core-sim
```

`reset --mixed` подкладывает под ваши файлы историю с сервера. Файлы на диске
при этом **не трогаются** — меняется только представление git о том, что считать
исходной точкой. Без этой команды получилась бы вторая независимая история,
и `push` отбился бы с сообщением про «unrelated histories».

**Если ветки на сервере нет** — ничего делать не нужно, она создастся при первой отправке.

## 1. Обычная отправка: командная строка

Четыре команды. Первые две — обязательный ритуал: посмотреть, что уходит.

```cmd
cd /d "C:\Users\sidef\Desktop\0-41-andy-branch"

git add -A
git status --short
```

`git status --short` печатает список файлов. **Прочитайте его.** Здесь должны быть
только файлы проекта: `scripts/`, `kontur-core/`, `data/`, `content/`, `docs/`.
Если мелькнёт что-то из домашней папки — не коммитьте, разберитесь сначала.

Строчки читаются так: `M` — файл изменён, `A` — добавлен, `D` — удалён,
`R` — переименован.

```cmd
git commit -m "очередь звонков и фабрика оперативников"
git push
```

Всё. Сообщение в кавычках — своими словами, что сделано; оно пригодится вам же
через месяц, когда будете искать, где что сломалось.

### Если очень часто

Одной строкой (`&&` — «выполняй следующее, только если предыдущее удалось»):

```cmd
git add -A && git commit -m "промежуточное сохранение" && git push
```

Но тогда вы не увидите список файлов перед коммитом. Для повседневной работы
годится, после долгого перерыва — лучше полный вариант.

## 2. Обычная отправка: VS Code

Откройте папку проекта: **File → Open Folder** → `0-41-andy-branch`.

Слева на панели — иконка ветвления (**Source Control**, `Ctrl+Shift+G`).
Там список изменённых файлов.

1. **Посмотрите изменения.** Клик по файлу открывает сравнение: слева было,
   справа стало. Полезно перед коммитом пробежать глазами.
2. **Добавьте файлы в коммит.** Плюсик рядом с заголовком *Changes* добавляет
   все сразу; плюсик у отдельного файла — только его.
3. **Напишите сообщение** в поле сверху.
4. **Commit** — синяя кнопка. Коммит пока только у вас на диске.
5. **Sync Changes** (или `Ctrl+Shift+P` → `Git: Push`) — отправка на сервер.

Внизу в строке состояния показана текущая ветка и стрелки со счётчиками:
↑ — сколько коммитов ждут отправки, ↓ — сколько пришло с сервера.

### Терминал прямо в VS Code

`` Ctrl+` `` открывает консоль уже в папке проекта — `cd` не нужен.

Одна оговорка: по умолчанию там **PowerShell**, а не `cmd`. Команды git те же,
но `cd /d` не работает — в PowerShell просто `cd`. Все команды из раздела выше
кроме `cd /d` переносятся один в один.

## 3. Что делать, когда не пускает

**Просит логин и пароль.** GitHub отменил вход по паролю в 2021 году. Должно
всплыть окно браузера с кнопкой авторизации — согласитесь, и дальше git запомнит
доступ. Если окна нет, поставьте [Git Credential Manager](https://github.com/git-ecosystem/git-credential-manager)
(он входит в стандартный установщик Git для Windows).

**`rejected — non-fast-forward` или `fetch first`.** На сервере есть коммиты,
которых нет у вас: работали с другой машины или через веб-интерфейс. Заберите их
и отправьте заново:

```cmd
git pull --rebase
git push
```

**`refusing to merge unrelated histories`.** Пропущен `git reset --mixed origin/core-sim`
из раздела 0 — у вас своя история, у сервера своя. Вернитесь к настройке.

**Ничего не отправляется, `nothing to commit`.** Правда нет изменений — либо файлы
попали под `.gitignore`. Проверить конкретный файл:

```cmd
git check-ignore -v путь/к/файлу
```

Команда печатает строку `.gitignore`, из-за которой файл игнорируется.
Пусто — значит, дело не в этом.

**Что-то лишнее уже закоммичено, но ещё не отправлено.** Отменить последний
коммит, сохранив изменения в файлах:

```cmd
git reset --soft HEAD~1
```

После `push` так уже не поправишь — история ушла на сервер.

## 4. Что в репозиторий не попадает и почему

Это описано в `.gitignore`:

- `.godot/` — кэш редактора, 25 МБ, пересоздаётся сам;
- `bin/`, `obj/` — результаты сборки .NET, тоже пересоздаются;
- `content/localisation/` — **собранный текст**. Генерируется конвертером из
  `content/raw`, поэтому в репозитории лишний. Но перед экспортом билда конвертер
  обязательно прогнать: `python content/engine/converter/build.py`, иначе в `.pck`
  не попадёт ни строчки текста;
- `*.old` — резервные копии конфигов после ручных правок;
- `.claude/`, `.mcp.json`, `AGENTS.md` — локальные настройки инструментов.
