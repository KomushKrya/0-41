# Интеграция в Godot-проект

> **Статус: мост подключён к основной сцене.** Ядро собирается отдельной сборкой,
> терминал запускает смены через ядро, а отладочный оверлей открывается в игре по F6.
> Телефон, карта, радио и остальные физические объекты подключаются к событиям ядра
> по мере реализации их игрового поведения.

## Что уже сделано

| Что | Где |
|---|---|
| Ссылка на сборку ядра | `kontur_prototype.csproj` → `ProjectReference` на `Kontur.Core.csproj` |
| Исключение исходников ядра из сборки игры | `kontur_prototype.csproj` → `Compile Remove="kontur-core\**\*.cs"` |
| Контент игры | `data/*.json` (9 файлов) |
| Чтение `res://` | `scripts/kontur/GodotContentSource.cs` |
| Мост-автозагрузка | `scripts/kontur/GameRuntime.cs`, зарегистрирован как `GameRuntime` в `project.godot` |
| Отладочный оверлей | `scripts/debug/KonturDebugOverlay.cs` + `scenes/debug/KonturDebug.tscn` |

Связанные с ядром автозагрузки идут в `project.godot` в таком порядке:

```ini
[autoload]

Content="*res://content/engine/content/Content.cs"
GameRuntime="*res://scripts/kontur/GameRuntime.cs"
```

## Единый источник истины

Старый слой `scripts/gameplay` удалён. Состояние партии хранит только
`Kontur.Core.Api.GameSession`, а события публикует `Kontur.Core.Events.EventBus`.

Сцены получают сеанс через `GameRuntime.Get(this).Session`. Они вызывают команды,
читают `Get*`-снимки и подписываются на `Session.Events`; собственные копии дня,
таймеров и фаз смены создавать не нужно.

## Как проверить

1. Закрыть запущенную игру, если она открыта: пока окно живо, DLL заблокирована
   и сборка молча не применится.
2. Собрать проект (молоток в правом верхнем углу), посмотреть вкладку **MSBuild**.
3. Запустить основную сцену и нажать **F6**, чтобы открыть отладчик ядра.
4. Нажать «Смена 1», затем «x5».
5. Кнопками провести вызов: «Ответить» → «ОК (метка)» → выбрать состав в панели
   «ОТПРАВКА ГРУППЫ» → «Отправить выбранных». При появлении радио — «Радио 1/2/3».

Три колонки оверлея: слева состояние ядра (фазы вызовов, шкалы, штат, склад,
энциклопедия, отчёты), в центре — экран отправки с галочками и предпросмотром расчёта,
справа — поток сигналов. Если ядро не поднялось, оверлей покажет причину.

Главная сцена (`main.tscn`) работает как раньше: автозагрузка загружает контент и молчит,
пока смена не начата — `Tick` при неактивной смене ничего не делает. Ошибка контента
не роняет игру: узел остаётся инертным, причина видна в Output и в `LoadError`.

## Единственный источник контента

После интеграции контент игры живёт в `data/`. `kontur-core/content/` — та же
копия для автономного прогона; харнесс теперь ищет сначала `data/`, потом `content/`,
так что консоль и игра читают одни и те же файлы. Папку `kontur-core/content/`
можно удалить, чтобы не расходились.

## Экспорт сборки

При настройке экспорта добавить `*.json` в **Filters to export non-resource files**,
иначе `data/` не попадёт в `.pck` и релизная сборка не найдёт контент.

## Шаг 1. Подключение сборки (сделано)

Версию `Godot.NET.Sdk` в csproj ядро не диктует — она остаётся такой, какой её держит
команда (сейчас `4.7.0`). Ядро собирается обычным `Microsoft.NET.Sdk` на `net8.0`
и от версии движка не зависит.

В `kontur_prototype.csproj`:

```xml
<ItemGroup>
  <Compile Remove="kontur-core\**\*.cs" />
  <None Remove="kontur-core\**" />
</ItemGroup>

<ItemGroup>
  <ProjectReference Include="kontur-core\src\Kontur.Core\Kontur.Core.csproj" />
</ItemGroup>
```

`Compile Remove` обязателен: `Godot.NET.Sdk` включает все `.cs` под корнем проекта,
и без него файлы ядра компилировались бы дважды. `Kontur.Harness` не подключается —
это инструмент разработки.

Откат интеграции = удаление `ProjectReference` (и строки автозагрузки).
Ядро при этом продолжает собираться само.

## Шаг 2. Контент в `res://` (сделано)

`data/*.json` читается через `GodotContentSource`: `System.IO` для `res://` не годится,
в экспортированной сборке ресурсы лежат в `.pck`, а не на диске.

## Шаг 3. Автозагрузка-мост (сделано)

`scripts/kontur/GameRuntime.cs`, в `project.godot`:

```ini
[autoload]

GameRuntime="*res://scripts/kontur/GameRuntime.cs"
```

Экспортируемые параметры: `ContentRoot`, `Seed`, `IsPaused`, `TimeScale`, `LogEvents`.
Ошибка контента не роняет игру — узел остаётся инертным, причина видна в Output
и в `LoadError`.

Доступ из любой сцены:

```csharp
GameRuntime runtime = GameRuntime.Get(this);
if (runtime != null && runtime.IsReady)
{
    runtime.Session.Events.Subscribe<IncidentCreated>(OnIncidentCreated);
}
```

## Шаг 4. Раскладка по предметам на столе (следующий шаг)

Каждое событие ядра имеет ровно одного «хозяина» в кабинете:

| Событие ядра | Кто реагирует | Что делает |
|---|---|---|
| `IncidentCreated` | Телефон | начинает звонить, запускает индикатор 15 с |
| `CallAnswered` | Телефон | показывает бланк задания |
| `CallMissed` | Телефон | обрывает звонок |
| `MapMarkerSpawned` / `MapMarkerExpired` | Карта | ставит/снимает метку, индикатор 30 с |
| `DispatchScreenRequested` | Компьютер | открывает экран отправки |
| `SquadDispatched` / `SquadArrived` | Карта | пунктирная линия маршрута (`DashedRouteRenderer` уже есть) |
| `RadioTriggered` / `RadioMissed` | Радиостанция | треск, экран вариантов, индикатор 20 с |
| `ScalesChanged` | Блокнот | анимация шкал (`NotebookDebugBars` уже умеет) |
| `MissionReportReady` / `CreatureRevealed` | Компьютер | отчёт и новый абзац энциклопедии |
| `EmployeeInjured` / `EmployeeKilled` | Досье | состояние портрета |
| `ShiftStarted` | Записка сменщика | текст записки |
| `ShiftEnded` | Менеджер сцен | пререндеренный ролик по `OutroCutsceneId` |
| `GameOverTriggered` | Менеджер сцен | финальный экран по причине |

Обратно от UI к ядру идут только команды `GameSession`:
`AnswerCall`, `ConfirmBriefing`, `OpenDispatchScreen`, `DispatchSquad`,
`ChooseRadioOption`, `SpendSkillPoint`, `HireEmployee`.

Каждая возвращает `CommandResult` — UI не гадает, разрешено ли действие.

## Правила, которые стоит удержать после мержа

1. **Ни одного `using Godot` в `Kontur.Core`.** Это не эстетика: как только
   зависимость появится, headless-прогон и самопроверки перестанут работать,
   и отлаживать баланс снова придётся через редактор.
2. **UI не читает `DebugState`.** Для интерфейса есть `Get*`-снимки. `DebugState`
   существует для отладочного оверлея и тестов.
3. **UI не хранит состояние игры.** Сцена может кэшировать то, что нужно для
   отрисовки, но истина — в ядре. Иначе рассинхрон при наложении вызовов.
4. **Балансные числа правятся в `content/config.json`,** не в сценах.
5. **Перед мержем правок баланса — `--selftest`.** Проверки таймингов, лимитов
   штата и формулы успеха стоят там именно для этого.

## Порядок работ после интеграции

1. Мост-автозагрузка + отладочный оверлей, показывающий фазы вызовов (без графики).
2. Телефон и карта — самый короткий замкнутый цикл: звонок → метка → отправка.
3. Компьютер: экран отправки, затем отчёты и энциклопедия.
4. Радиостанция.
5. Блокнот и досье (в основном уже есть).
6. Ролики и финальные экраны.
