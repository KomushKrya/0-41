# Kontur.Core — симуляционное ядро К.О.Н.Т.У.Р.

Внутренняя («невидимая») часть игры: правила, таймеры, расчёты, состояние.
Ни одной строчки, зависящей от Godot. Собирается, запускается и отлаживается сама по себе.

> **Статус:** ядро подключено к Godot-проекту как отдельная сборка. Мост-автозагрузка
> `GameRuntime`, терминал запуска смены и отладчик с экраном отправки работают через единый
> `GameSession`. Старый параллельный слой `scripts/gameplay` удалён.
> Проверка в движке: запустить основную сцену и нажать F6.
> Справочник для тех, кто прикручивает интерфейс — `docs/ЯДРО-API.md` в корне проекта.

## Зачем отдельно

Прототип правил и боевой код игры имеют разный темп изменений. Пока баланс и
жизненный цикл смены не устоялись, держать их внутри сцен Godot — значит каждый
эксперимент с формулой тащить через редактор, сцены и мета-файлы.

Поэтому:

* ядро живёт в отдельной ветке репозитория и в отдельной папке `kontur-core/`;
* Godot-проект о нём пока ничего не знает;
* интеграция после отладки — одна строка `ProjectReference` и слой адаптеров
  (см. `docs/INTEGRATION.md`).

## Быстрый старт

```bash
cd kontur-core

# самопроверка инвариантов ядра
dotnet run --project src/Kontur.Harness -- --selftest

# прогон 4 игровых дней в консоли
dotnet run --project src/Kontur.Harness -- --days 4 --seed 41 --strategy best

# «плохой оператор»: медленно берёт трубку, выбирает заведомо провальные варианты
dotnet run --project src/Kontur.Harness -- --days 4 --strategy worst --answer-delay 20
```

Ключи харнесса:

| Ключ | Значение |
|---|---|
| `--seed N` | зерно ГПСЧ; один seed — один и тот же прогон |
| `--days N` | сколько смен прогнать (1–4) |
| `--dt X` | шаг симуляции в секундах (по умолчанию 0.25) |
| `--strategy best\|worst\|random\|ignore` | как автопилот отвечает по радио |
| `--answer-delay X` | задержка ответа на звонок; > 15 с даёт пропуски |
| `--dispatch-delay X` | задержка отправки группы; > 30 с даёт просрочку метки |
| `--verbose` | подробный лог (опыт, расход снаряжения, закрытие вызовов) |
| `--content PATH` | путь к папке с JSON-контентом |
| `--selftest` | прогнать проверки инвариантов и выйти |

## Структура

```
kontur-core/
  src/Kontur.Core/        ядро (без Godot)
    Events/               шина событий и список сигналов из раздела 13 ДД
    Simulation/           таймеры и детерминированный ГПСЧ
    Model/                доменные типы: сотрудники, снаряжение, существа, здания, шкалы
    Content/              загрузка и валидация JSON-контента
    Config/               все балансные числа
    Systems/              правила: смена, миссии, шкалы, энциклопедия, штат
    Api/                  GameSession — единственная точка входа для UI
  src/Kontur.Harness/     консольный прогон + автопилот + самопроверки
  content/                JSON-контент (заглушки под текстовый движок)
  docs/                   архитектура, схема контента, план интеграции
  integration/            эскизы адаптеров для Godot (в проект пока не копируются)
```

## Контент

Источник истины — `data/*.json` в корне Godot-проекта. Харнесс ищет сначала `data/`,
затем `content/`, поэтому консольный прогон и игра читают одни и те же файлы.
Копия в `kontur-core/content/` (была нужна для автономного запуска) удалена —
разошлась с `data/` и ломала харнесс без явного `--content`; запускать
самотест теперь строго через `--content data`.

## Что уже реализовано

Раздел 3 ДД целиком: звонок (15 с) → бриф → метка (30 с) → отправка → движение →
прибытие → радио (20 с) → расчёт → шкалы → травмы/гибель → возвращение → отчёт →
энциклопедия. Наложение вызовов, окно приёма 5 минут, завершение
смены по закрытию последнего вызова, три условия game over.

Сверх ДД: обучающая смена. День 1 идёт по сценарию, вызовы приходят по одному,
таймеры игрока отключены — механику невозможно промотать мимо. Задаётся тремя полями
в `config.json`, кода не касается.

## Чего сознательно нет

* Никакого рендеринга, ввода, сцен, звука — это слой Godot.
* Никакой генерации текста — тексты приходят готовыми из JSON (раздел 14 ДД).
* Никакого сохранения/загрузки — добавляется отдельно поверх `GameState`.
