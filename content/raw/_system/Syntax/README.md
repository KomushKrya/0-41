# Схема фронтматтера и кастомных тегов (черновик)

Черновик — конвертер (`content/engine/converter`) это ещё не парсит. Примеры полей
смотри в `_system/Templates/`, здесь только то, что не очевидно из шаблонов.

## Общие поля

`id` (уникален по всему `content/raw`, не по папке), `type`, `status: draft|ready`
(конвертер пропускает `draft`). Реестр `id` — `_system/ids_registry.md`, генерируется
конвертером автоматически.

**Принцип:** во фронтматтере — только текстовые поля (тип, статус, `kind`/`name`).
Механические данные (требования миссии, привязка происшествия к существу/событию) —
геймдизайн на стороне Godot, ссылается на текст по `id`, а не наоборот. Исключение,
которое ещё не пересмотрено: `report.incident_id`/`report.creature_id`.

## Типы

- **bottom_text** — звонки (`kind: call`) и катсцены (`kind: cutscene`), один виджет
  нижнего текста. Тело — абзацы, пустая строка = один клик.
- **mission_event** — события на выездах (бывший `radio`). Вводная как chunked-абзацы,
  затем секции `## Вариант: <название>` (`requirement_modifier`, `canon`). Количество
  вариантов не фиксировано, но сами варианты обязательны.
- **creature** — 4 абзаца, первый виден сразу, остальные три — под `%% reveal: id %% ...
  %% /reveal %%`.
- **shift_note**, **report** — без изменений в последнем пересмотре.

## Кастомные inline-теги

- `[[type:id]]` — кросс-ссылка на другой контент; конвертер должен падать на билде,
  если цель не найдена.
- `%% reveal: <property_id> %% ... %% /reveal %%` — условный блок; движок только
  маркирует условность, показывать или нет решает игра.
