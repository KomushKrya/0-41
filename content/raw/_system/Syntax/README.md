# Схема фронтматтера и кастомных тегов (черновик)

Черновик — конвертер (`content/engine/converter`) это ещё не парсит. Примеры полей
смотри в `_system/Templates/`, здесь только то, что не очевидно из шаблонов.

## Общие поля

`id` (уникален по всему `content/raw`, не по папке), `type`, `status: draft|ready`
(конвертер пропускает `draft`). Реестр `id` — `_system/ids_registry.md`, генерируется
конвертером автоматически.

**Принцип:** во фронтматтере — только текстовые поля (тип, статус, `kind`/`name`) плюс
`requirements` — список условий/флагов показа (например, сюжетный выбор в предыдущем
событии), который движок только передаёт как есть, не проверяя. Это не то же самое, что
числовые требования миссии (характеристики группы и т.п.) — те остаются геймдизайном на
стороне Godot и в `.md` не хранятся. `report` тоже избавлен от связок (`incident_id`,
`creature_id`) — остался только `outcome`.

Все типы теперь также несут `properties` — список id именованных под-блоков внутри
тела файла (пока реально используется только у `creature`, для `%% reveal %%`; у
остальных типов это задел на будущее, если появятся свои условные под-блоки).

## Типы

- **call** / **cutscene** — входящие звонки и катсцены (переходы, интро, финалы), оба
  показываются одним виджетом нижнего текста (абзацы, пустая строка = один клик). У
  обоих есть `requirements` — условия, при которых контент должен появиться/запуститься.
  Виджет прозрачный и без фона, текст центрирован — поэтому **один абзац это максимум
  две строки** (ориентир — 150 символов, конвертер предупреждает при превышении). Длинную
  мысль дробим на несколько абзацев, а не пишем простынёй.
- **mission_event** — события на выездах (бывший `radio`). Тоже есть `requirements`.
  Вводная как chunked-абзацы, затем секции `## Вариант: <название>` (`requirement_modifier`,
  `canon`). Количество вариантов не фиксировано, но сами варианты обязательны.
- **creature** — тоже есть `requirements`. Плюс `properties` — список id всех скрытых
  свойств существа (по одному на каждый `%% reveal %%`-блок в теле), чтобы было видно,
  что вообще доступно, не читая весь файл. 4 абзаца, первый виден сразу, остальные три —
  под `%% reveal: id %% ... %% /reveal %%` с `id`, совпадающим с одним из `properties`.
- **shift_note**, **report** — без изменений в последнем пересмотре.

## Кастомные inline-теги

- `[[type:id]]` — кросс-ссылка на другой контент; конвертер должен падать на билде,
  если цель не найдена.
- `%% reveal: <property_id> %% ... %% /reveal %%` — условный блок; движок только
  маркирует условность, показывать или нет решает игра.

- Формат `requirement_modifier` (абсолют/процент/по конкретной характеристике)?
