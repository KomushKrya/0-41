# Схема фронтматтера и кастомных тегов (черновик)

Черновик — конвертер (`content/engine/converter`) это ещё не парсит. Примеры полей
смотри в `_system/Templates/`, здесь только то, что не очевидно из шаблонов.

## Общие поля

`id` (уникален по всему `content/raw`, не по папке), `type`, `status: draft|ready`
(конвертер пропускает `draft`). Реестр `id` — `_system/ids_registry.md`, генерируется
конвертером автоматически.

**Принцип:** во фронтматтере — только текстовые поля (тип, статус, `kind`/`name`) плюс
`requirements` — список условий/флагов показа (например, сюжетный выбор в предыдущем
событии), который движок только передаёт как есть, не проверяя. Это не то же самое, что
числовые требования миссии (характеристики группы и т.п.) — те остаются геймдизайном на
стороне Godot и в `.md` не хранятся. `report` тоже избавлен от связок (`incident_id`,
`creature_id`) — остался только `outcome`.

Все типы теперь также несут `properties` — список id именованных под-блоков внутри
тела файла (пока реально используется только у `creature`, для `%% reveal %%`; у
остальных типов это задел на будущее, если появятся свои условные под-блоки).

## Типы

- **call** / **cutscene** — входящие звонки и катсцены (переходы, интро, финалы), оба
  показываются одним виджетом нижнего текста (абзацы, пустая строка = один клик). У
  обоих есть `requirements` — условия, при которых контент должен появиться/запуститься.
  Виджет прозрачный и без фона, текст центрирован — поэтому **один абзац это максимум
  две строки** (ориентир — 150 символов, конвертер предупреждает при превышении). Длинную
  мысль дробим на несколько абзацев, а не пишем простынёй.
- **mission_event** — события на выездах (бывший `radio`). Тоже есть `requirements`.
  Вводная как chunked-абзацы, затем секции `## Вариант: <название>`. У варианта четыре
  метаполя: обязательные `id` и `quality`, необязательные `requirement_modifier`
  и `requires`. Количество вариантов не фиксировано, но сами варианты обязательны.

  `quality` — `good` | `neutral` | `bad`. Это тип диалога: он задаёт умолчания надбавки
  и рисков, если числа не написаны руками. Конвертер падает, если тип разошёлся с ценой:
  хороший вариант не может быть дороже плохого.

  `requires` — порог по характеристикам группы: `requires: ловкость 6, хладнокровие 4`.
  Ниже порога вариант закрыт — игрок видит его неактивным с причиной. Считается по уже
  отправленному отряду, так что состав, собранный на экране отправки, решает, какие
  решения останутся доступны. Имена характеристик принимаются и русские, и латиницей.

  **Хотя бы один вариант обязан быть без `requires`** — иначе слабой группе будет нечего
  выбрать, а таймер радио идёт. Конвертер это проверяет.
- **creature** — тоже есть `requirements`. Плюс `properties` — список id всех скрытых
  свойств существа (по одному на каждый `%% reveal %%`-блок в теле), чтобы было видно,
  что вообще доступно, не читая весь файл. 4 абзаца, первый виден сразу, остальные три —
  под `%% reveal: id %% ... %% /reveal %%` с `id`, совпадающим с одним из `properties`.
- **perk** — спецспособности сотрудников, лежат в `UI/perks/` (единственный тип во
  вложенной папке: `UI/` — задел под остальной интерфейсный текст, сама она контент
  не держит). `name` — как перк подписан в досье, тело — описание. `id` совпадает с
  id способности в `data/abilities.json`: числовая часть (`condition`, `bonus`,
  `allStatsBonus`) остаётся там и ссылается на текст по id.
- **shift_note**, **report** — без изменений в последнем пересмотре.

## Кастомные inline-теги

- `[[type:id]]` — кросс-ссылка на другой контент; конвертер должен падать на билде,
  если цель не найдена.
- `%% reveal: <property_id> %% ... %% /reveal %%` — условный блок; движок только
  маркирует условность, показывать или нет решает игра.
- `%% call_meta: <текст> %%` — служебная шапка звонка («ЗВОНОК ПЕРЕНАПРАВЛЕН ИЗ ЖЭК»,
  «НА ЛИНИИ НАПУГАННО ЗВУЧАЩИЙ СТАРИК»). Отдельной строкой; попадает в куски своим
  `kind: call_meta` вместо `kind: text`, чтобы виджет рендерил её не как реплику.
  Квадратные скобки в текст не пишем — это оформление, его добавляет виджет.
  Ограничение на две строки к шапке не применяется. Доступен только у `call` и
  `cutscene` — на остальных типах это ошибка сборки.
- `{{имя}}` — подстановка значения из геймплейных данных: `+{{bonus.strength}} к силе`
  вместо захардкоженного `+2`. Движок значений не знает и не подставляет — он только
  помечает место и собирает все имена записи в поле `variables` в JSON, чтобы игра
  видела, что ей нужно заполнить (`Content.Fill(text, values)`). Имя — буквы, цифры и
  `_`, вложенность через точку; пробелы внутри скобок и непарные скобки — ошибка
  сборки. Знак `+` пишется в тексте руками, подставляется только число.
  Намеренно не `%%`: Обсидиан прячет `%%...%%` в режиме чтения, а плейсхолдер должен
  оставаться видимым автору при вычитке.
- `%% dev: <текст> %%` — инлайн-заметка для разработчиков, вырезается конвертером до
  разбора кусков, так что в JSON и в игру не попадает вообще. Многострочная форма —
  `%% dev %% ... %% /dev %%`. Здесь и живёт всё, что по схеме не должно лежать в
  тексте: описание задания, заложенные требования по характеристикам, эффекты исхода
  на заражение/гласность/лояльность, подсказки диспетчеру. Незакрытый тег — ошибка
  сборки. Обсидиан `%%`-комментарии тоже не показывает, поэтому в режиме чтения
  заметка не мешает.
