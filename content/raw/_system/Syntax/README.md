# Фронтматтер и теги

Примеры полей — в `_system/Templates/`, здесь только то, что не очевидно из шаблонов.

## Общие поля

`id` (уникален по всему `content/raw`; у `perk`, `characteristic`, `equipment` совпадает
с id в геймплейных данных), `type`, `status: draft|ready` — конвертер пропускает `draft`.

`requirements` — флаги, при которых запись вообще может появиться. Движок их не проверяет,
только передаёт. Числовые требования миссий живут на стороне Godot и сюда не попадают.

`properties` — id условных под-блоков внутри записи. Реально работает только у `creature`.

## Типы

| Тип | Особенности |
|---|---|
| `call` | `mission_type: radio\|filler`, `requires: харизма, интеллект` (у филлера — минимум две характеристики). Шапка `%% call_meta %%`, дальше абзацы. Ключевые слова `==...==`. |
| `cutscene` | Виджет нижнего текста: кусок ≤150 символов, иначе не влезет в две строки. |
| `radio` | Вводная, затем `## Вариант: <название>` с полями `id` и `requires`. Вариант доступен всегда; без `requires` — значит проверять нечего. Минимум один вариант. |
| `creature` | 4 абзаца: первый открыт, остальные под `%% reveal %%`, id блоков = `properties`. |
| `report` | `outcome`. |
| `shift_note` | `day`. |
| `equipment` | `name`. Вид, бонусы и множители — в `data/equipment.json`. |
| `perk` | `name`. Числа — в `data/abilities.json`. |
| `characteristic` | `name`. Id = `StatKinds.GetId(kind)`, названий ядро не знает. |
| `equipment_kind` | `name`. Сноска по наведению. Id — `consumable`, `standard`, `story`. |
| `scale` | `name`. Id = `ScaleKinds.GetId(kind)`: `infection`, `publicity`, `loyalty`. |

## Пороги характеристик

`requires` — это перечисление характеристик через запятую, без чисел:
`требуется: интеллект, харизма`. Допустимы пять — **сила**,
**боевая подготовка**, **ловкость**, **харизма**, **интеллект**; они же лежат
в `UI/hover_footnote/characteristics/`. Незнакомое название и любое число роняют
сборку, чтобы опечатка не превратилась в «проверки нет».

Порога в тексте нет намеренно: порог — это требование миссии по той же
характеристике, и живёт оно в `data/missions.json`. Текст отвечает на вопрос
«что проверяем», данные — «насколько трудно». Иначе одно и то же число пришлось бы
держать синхронным в двух местах.

## Теги

- `**слово**` — жирный: подписи и ярлыки, всё, что не речь.
- `==слово==` — ключевое слово вызова, виджет красит его `#d27253`. Характеристику тег не
  несёт: сопоставить — работа игрока. Перечень слов — `_system/Keywords.md`.
- `[[тип:id]]` — кросс-ссылка. Битая ссылка роняет сборку. В рантайме **не разворачивается**,
  поэтому в показываемый игроку текст её не ставим.
- `%% reveal: <property_id> %% … %% /reveal %%` — условный блок. Показывать или нет,
  решает игра.
- `%% call_meta: <текст> %%` — шапка звонка: откуда звонят и кто на линии. Отдельной
  строкой; едет своим куском, чтобы интерфейс показал её отдельно от реплик, а не
  как первую фразу собеседника. Скобки добавляет интерфейс.
  Только у `call` и `cutscene`, ограничение на две строки к ней не относится.
- `{{имя}}` — число из геймплейных данных: `+{{bonus.strength}} к силе`. Конвертер собирает
  имена в поле `variables`, подставляет игра. Имя — буквы, цифры и `_` через точку.
- `%% dev: <текст> %%` и `%% dev %% … %% /dev %%` — заметка для разработчиков, вырезается
  до разбора кусков. Пишем коротко: флаги, связи, проверки. Незакрытый тег — ошибка сборки.

`%%`-теги Обсидиан прячет в режиме чтения, `==` и `**` показывает — потому подсветка и
жирный сделаны markdown-ом, а служебное — комментариями.
